# ADR 0001: 단일 클라우드 멀티리전 대신 GCP + AWS 멀티클라우드 DR

- 상태: 제안됨
- 날짜: 2026-10-10

## 맥락

PayFlow는 결제 플랫폼으로, 장애 시 거래 손실과 신뢰도 하락이 크다. Primary는 GCP 서울 리전(asia-northeast3)이다.

## 고려한 대안

| 대안 | 막을 수 있는 장애 | 한계 |
|---|---|---|
| 단일 리전 Multi-AZ | 존(Zone) 장애 | 리전 장애 대응 불가 |
| GCP 멀티리전 | 리전 장애 | 국내 데이터 보관 전제 시 국내 2번째 리전 없음, CSP 전체 장애 대응 불가 |
| **GCP + AWS (선택)** | 리전 장애 + CSP 전체 컨트롤 플레인·IAM 장애, 계정 정지 | 복잡도, egress 비용, 두 클라우드의 공통 기능만 사용 |

## 결정

AWS 서울 리전을 Warm Standby로 하는 멀티클라우드 DR을 구축한다.

## 근거

1. 국내 데이터 보관을 전제로 하면 GCP 단독으로는 국내 리전 이중화가 불가능하다.
2. CSP 전체 범위 장애 사례가 실제로 존재한다 (2025-06 GCP Service Control, 2025-10 AWS us-east-1).
3. DORA 등은 멀티클라우드를 의무화하지 않지만 CSP 집중 리스크 관리와 Exit Strategy를 요구한다. 본 프로젝트는 그 실행 가능성을 검증한다.

## 결과

- (+) CSP 단위 장애에서도 서비스 지속 가능
- (−) 운영 복잡도 증가, 클라우드 간 데이터 전송 비용 발생
- (−) Kubernetes·PostgreSQL 등 클라우드 중립 기술로 선택지가 제한됨
- 완화: Warm Standby로 평시 비용 최소화, IaC·GitOps로 환경 차이 최소화
